## Аппаратные требования

Значения получены измерением, а не оценочно. Профиль потребления ресурсов полным пайплайном
(физика и рендеринг Gazebo, PX4 SITL, мост uXRCE-DDS, YOLO + ByteTrack, ReID, ноды ROS2) в
режиме слежения на сцене `follow_crowd.sdf`; замер выполнен утилитой `nvidia-smi` 2026-07-22
(Инкремент 9B, `docs/phase4_setup.md` §8).

**Референсная конфигурация (на которой проект собран и функционирует):**

| Ресурс | Значение |
|---|---|
| CPU | Intel Core i7-11800H, 8 ядер / 16 потоков |
| RAM | 32 ГиБ |
| GPU | NVIDIA RTX 3050 Ti Laptop, **4 ГиБ VRAM**, драйвер 580 (CUDA-совместимый), **гибридная графика** (Intel iGPU + NVIDIA dGPU) |
| Диск | NVMe SSD |

**Измеренное потребление ресурсов в установившемся режиме слежения (TRACK):**

| Метрика | Значение | Примечание |
|---|---|---|
| Загрузка GPU (`sm`) | **~30 %** | вычислительно не является узким местом |
| Занятая VRAM | **~1.5 ГиБ из 4 ГиБ** | `python` (YOLO + ReID) 836 МиБ, сервер и GUI Gazebo ~540 МиБ, Xorg ~23 МиБ |
| Латентность инференса | **~10 мс/кадр** | YOLOv8n + ByteTrack |
| Частота детекции | **~30 кадр/с** | ограничена частотой камеры (30 Гц), а не производительностью GPU |

**Минимальные и рекомендуемые требования (обоснованы измерениями):**
- **GPU: дискретный адаптер NVIDIA с поддержкой CUDA — обязателен.** Потребление VRAM в
  установившемся режиме составляет ~1.5 ГиБ, однако при загрузке модели ReID одновременно с
  рендерингом зафиксирован кратковременный пик, приведший к исчерпанию VRAM (OOM) на адаптере
  с 4 ГиБ (Инкремент 8). Вывод: **4 ГиБ VRAM — рабочий минимум с ограниченным запасом, ≥6 ГиБ —
  рекомендуемый объём.** Для YOLO и ReID реализован откат на CPU, однако он неприемлем по
  задержкам для режима реального времени, а рендеринг Gazebo в любом случае требует GPU.
  Для адаптеров с меньшим объёмом VRAM предусмотрены параметры снижения нагрузки
  (`detect_every_n`, `half`/fp16, `imgsz` — `docs/phase4_setup.md` §8, Инкремент 9B).
- ⚠️ **При гибридной графике запуск обязателен с `GPU=nvidia`** (вычисления и рендеринг
  выносятся на дискретный адаптер). В противном случае рендеринг Gazebo на встроенном адаптере
  конкурирует с YOLO за ресурсы GPU, что нарушает lockstep: PX4 теряет данные сенсоров
  (`Arming denied`), качество изображения с камеры снижается. Ранее это являлось основной
  причиной отказа арминга — подробности в `docs/phase3_setup.md` §9.
- **RAM: 16 ГиБ достаточно** (проверено на 32 ГиБ со значительным запасом); потребление памяти
  умеренное.
- **Диск: не менее 20 ГиБ свободного пространства** для полного стека — исходный код
  PX4-Autopilot (`~/src/`, включая сборку), окружение venv с пакетами torch и CUDA (несколько
  ГиБ), веса моделей (YOLOv8n ~6 МБ, CLIP ViT-B-32 ~350 МБ).
- **CPU:** физика PX4 SITL, Gazebo, мост и ноды ROS2 создают многопоточную нагрузку;
  современный 8-ядерный процессор справляется без затруднений. Строгий минимум не измерялся;
  ориентировочная нижняя граница — 4 ядра.

## Окружение

Нативная установка, без Docker (на этапе локальной разработки):
- ROS2 Humble — системно через apt (`/opt/ros/humble`).
- venv с `--system-site-packages`, чтобы ноды видели и системный `rclpy`, и pip-зависимости.
- Создание/обновление venv — скриптом `scripts/setup_venv.sh` (поверх системного python 3.10,
  ставит зависимости из `requirements.txt`). conda не используем — он тянет свой интерпретатор/ABI
  и ломает линковку против системного ROS2.
- pip-зависимости (`torch`, `ultralytics`, `opencv-python`) — в `requirements.txt`.
  **numpy зафиксирован `<2`**: ROS2 Humble / cv_bridge собраны под numpy 1.x.
- Активация для работы — нужны **оба слоя**, но **порядок между ними не важен**
  (проверено 2026-06-11: `venv→ROS2` и `ROS2→venv` дают идентичный `sys.path` — тот же
  python из venv, numpy 1.26.4 из venv, rclpy из `/opt/ros/humble`). Минимальный набор:
  ```bash
  source /opt/ros/humble/setup.bash   # rclpy + PYTHONPATH/LD_LIBRARY_PATH/AMENT_PREFIX_PATH
  source install/setup.bash           # пакеты drone_* (после colcon build)
  source .venv/bin/activate           # torch/ultralytics; в терминале PyCharm уже активен
  ```
  Маркер готовности: `echo $ROS_DISTRO` → `humble`. Единственное жёсткое «нельзя» —
  **conda** (свой интерпретатор/ABI ломает линковку против системного ROS2); обычный
  `venv --system-site-packages` безопасен в любом порядке.
- `source install/setup.bash` пересорсить **обязательно** в новом терминале и при изменении
  состава пакетов (добавил/переименовал). При инкрементальной пересборке того же набора в
  том же терминале — не обязательно (env указывает на те же пути), но привычка полезна.

Пошаговое воспроизведение — `docs/phase2_setup.md`.

> ⚠️ `empy` ставится pip'ом как пакет `empy`, но **импортируется как модуль `em`** — это не ошибка.
> В `Tools/setup/requirements.txt` PX4 есть несовместимый с новым pip спек `matplotlib>=3.0.*`
> (`.*` с `>=`). Обход — санитайз на лету: `pip install -r <(sed 's/\.\*//g' …/requirements.txt)`.
