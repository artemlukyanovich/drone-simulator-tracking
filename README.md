# drone-simulator-tracking

Vision-guided drone control in simulation: a drone autonomously tracks and follows a
target it detects through its own camera. The control half of the `ai_drones` ecosystem
(the perception half is [`real-time-object-counter`](../../project_1/real-time-object-counter)).

```
Drone → Camera → Detector → Tracking → Decision → Move
```

## Status

🚧 **Early scaffold.** Repository structure and planning are in place; no runtime code yet.
The authoritative plan, decisions, and principles live in
[`docs/project_plan.md`](docs/project_plan.md) (Russian) — read it first.

## Goal

Learn to **control a system**, not just recognize an image, and work close to real UAV
stacks. `project_1` answers *"what do I see"*; this project answers *"how do I move based
on what I see"*.

## Tech stack

- **Gazebo** (gz-sim) — physics + sensors
- **PX4 SITL** — real autopilot, software-in-the-loop
- **ROS2** (LTS) — middleware, nodes, topics
- **uXRCE-DDS** + `px4_msgs` — native PX4 ↔ ROS2 bridge
- **ros_gz_bridge** — Gazebo camera → ROS2 `sensor_msgs/Image`
- **YOLO** (ultralytics) — detector (logic ported from `project_1`)

> ⚠️ PX4 / Gazebo / ROS2 versions are tightly coupled. Pin a compatible triple before
> writing code (see `docs/project_plan.md` §4, §11).

## Structure

This is a **colcon workspace**, not a flat Python project:

```
src/                 ROS2 packages (ament_python)
  drone_simulator/   SITL launch, bridges, world/drone description
  drone_perception/  detector_node — YOLO over the camera topic
  drone_control/     follower_node — offboard control loop, PID
  drone_bringup/     launch files that wire the pipeline together
configs/             simulator / perception / control parameters
outputs/             videos / logs / telemetry  (gitignored)
scripts/             run_px4_sitl.sh, bridges, demos
docs/                project_plan.md and other docs (Russian)
build/ install/ log/ generated by colcon (gitignored)
```

## Working with the repo

Open **this folder** as the project root in PyCharm and Claude Code — it is the git root,
the venv root, and the colcon workspace root. Do not open the parent `ai_drones/` as the
project root (see `docs/project_plan.md` §7).

## How to run

To be defined as packages are implemented (Phase 1). The general ROS2 flow will be:

```bash
colcon build
source install/setup.bash
ros2 launch drone_bringup tracking_demo.launch.py
```
